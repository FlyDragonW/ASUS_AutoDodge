# v2 / COCO l / v4l Unity 比較（執行前固定）

- 沿用 20261013-v2-unity 的 48 個 fusion 條件與順序、相同控制器、場景、相機、FP32 輸入、信心 0.60、350 ms 時效、10 Hz 排程。配對設定逐位元複製。
- 每版先 smoke 與同一張 RGB 的 Unity GPU / CPU ORT 數值驗證，再依 v2、COCO l、v4l 順序各跑 48 案。每條件一次即時執行，非統計顯著性實驗。
- 額外各四案：20/40 km/h × 受阻保持至少 6 s / 12 s 移除障礙後恢復。沿用先前條件，僅取 fusion 組。
- Runtime 只擴充模型選擇，預設仍 v2。benchmark 只新增渲染影格數、讀回時已超過 350 ms 的影格數、TryGetEvidence 成功的新鮮配對影格數；不改任何控制決策。
- COCO l 保留原始權重，ONNX 僅 Gather [0,1,2,3,6,7]，將 80 類輸出轉為汽車與機車介面；v4l 直接使用已評估的兩類模型。
- 各次啟動／結束記錄 GPU 溫度、時脈。延遲為相機擷取至 GPU 結果讀回，含渲染與排程。筆電熱節流、依序測試、非確定性時序限制比較。
- 報告所有碰撞／超時／退化。空路與路旁車輛有介入的案例才計入不必要介入；配對影格數不是危險物體辨識召回率。
- ACDC 已知分數僅作背景，不在此輪重測或據此改控制門檻。
